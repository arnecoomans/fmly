Mirrors get_full_name()'s own branches exactly (see Person.py), except called_name is highlighted within given_name instead of shown as a separate token, and the whole thing links to the person's page when this viewer may open it (person_url: a private person only for themself and their parents - people/privacy.py). Gated on visible_to(request.user) first - a person can be linkable yet still not visible to THIS viewer (e.g. Eric is public and links to his own page, but his community-visibility relatives shouldn't show their real name or a link to an anonymous visitor just because they appear in a row on Eric's page). When hidden, render an obfuscated name instead, and never a link. Context: `person` (Person instance). Optional `lifespan` (bool, default falsy) - when true, appends "(birth_year-death_year)" after the name, e.g. {% include '...get_full_name.html' with person=parent lifespan=True %}. Only shown in the visible branch, never alongside the obfuscated fallback - an exact birth year is itself an identifying detail, not something to leak just because the name next to it was hidden. The API is expected to also supply `object`/`field` when invoking this generically - not used here since this template is dedicated to one specific field already. `request` is expected too (already in scope via the request context processor for a normal page render; a future API render with no full request needs to supply at least `request.user`, or None -
